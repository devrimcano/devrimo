## Priority findings

### P1: Sensitive error text can reach analytics

High confidence in the code path; actual sensitive production payloads unverified.
Scholar hides normal workspace tool outputs but includes raw exception text in
`$ai_error` at `backend/app/agents/scholar/hooks.py:168`. Browser error capture
also forwards API-derived exception messages at
`frontend/components/posthog-analytics.tsx:146` and
`frontend/lib/api/fetcher.ts:17`. Other raw failure paths exist in
`backend/app/assistant/events.py:106` and
`backend/app/observability/turns.py:239`.

If an upstream error echoes student records or message content, it crosses the
telemetry boundary. Replace raw exception text with allowlisted error codes,
types, request IDs, and fingerprints. Secret-pattern scrubbing does not establish
that arbitrary academic or message content is absent.

### P1: Legacy catalog writes are global for scoped campus administrators

High confidence; active only while both academic catalog ingestion and reads are
disabled. `backend/app/api/v1/knowledge_admin.py:904` permits `planning_write`
to update legacy `CourseOffering` and `CourseRule` rows without organization
scope. Campus administrators receive this permission at
`backend/app/admin/auth.py:62`; the models at `backend/app/db/models.py:614`
have no organization column. The legacy planner reads the global rows at
`backend/app/planning/service.py:738`.

An administrator authorized for one organization can modify the catalog shared
by others on this branch. Remove the legacy write for scoped administrators or
migrate its storage and consumers to tenant scope. The new reviewed path is
organization-scoped; production flag values remain unverified.

### P1 candidate: SAIS response identity is inferred from the request

High confidence in the missing check; wrong-detail behavior was not reproduced
live. `backend/vendor_patches/course_info/sais_client.py:659` parses generic
detail tables and returns the requested `course_code` at line 738. Constraint
parsing has the same request-derived identity pattern at line 547. The client
documents stateful previous-page behavior at line 1014. Existing tests reject
a stale listing page, not a plausible stale detail page.

A previous course's detail could therefore be labeled as the requested course.
Require response-derived course, term, and section identity and reject ambiguous
responses. Add stale-detail and stale-constraint regression fixtures before
treating this as a proven reproduction.

## Security review qualifications

The scoped-admin legacy catalog write is the strongest confirmed tenant-boundary
finding. Additional static observations from the security reviewer:

- **P2, high static confidence: configurable embedding destinations lack an
  operator-approved destination policy.** `knowledge_admin.py:126` accepts any
  HTTP(S) hostname for local providers; campus administrators with
  `knowledge_write` can persist it at line 701. `knowledge/embeddings.py:142`
  posts corpus text and any configured API key to that endpoint. With indexing
  enabled, this permits server-origin requests to admin-selected destinations.
  Local/private endpoints are an intended feature, so a blanket private-IP ban
  is inappropriate. Establish who may approve destinations, allow intended local
  services explicitly, and constrain worker egress. Treat exfiltration severity
  according to whether a scoped admin is authorized to choose external providers.
- **Defense in depth:** catalog database policies are role-wide, not tenant-wide
  (`backend/alembic/versions/0033_academic_catalog.py:564`). Tenant isolation
  depends on application queries and cross-tenant FK guards. This alone is not
  proof of a reachable cross-tenant API exploit.
- **Rejected exploit claim:** unvalidated knowledge links were suggested as a
  `javascript:` stored-XSS vector. The installed React DOM implementation blocks
  that scheme in URL sinks (`react-dom-client.development.js:3166`). Keep URL
  normalization as hardening; do not report this vector as confirmed stored XSS.
- Deployment can fall back to migration credentials when separate backup
  credentials are absent (`scripts/deploy-vps.sh:27`). The observed backup
  succeeded. This is a least-privilege/configuration concern, not a failed backup.
